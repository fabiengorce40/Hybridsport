# M3.1 — séances non placées et HYROX équilibré

Base : `292e2e6` (M3). Deux problèmes produit observés sur téléphone.

## 1. « Non planifiée » ≠ « impossible »

**Cause racine** : une demande `unplaced` ne portait aucune séance. Le planificateur jetait la prescription générée sur les jours essayés (interférence) ou ne générait rien du tout (`NOT_ENOUGH_DAYS`). Programme et app-core n'acceptaient de résultat que pour une demande `planned`.

**Contrat** (`packages/planner/src/model.ts`) — sans renommer les statuts existants :

| Placement (`placementOf`) | Contrat | UI |
|---|---|---|
| `PLANNED` | `status: 'planned'` (prescription + jour) | carte normale |
| `COMPOSED_BUT_UNPLACED` | `status: 'unplaced'` + `composed` (séance, record, empreinte, profil de demande, créneau de **référence**) | carte « Non planifiée » + Voir / Faire maintenant |
| `BLOCKED` | `refused`, ou `unplaced` sans `composed` | carte « Non planifiée », aucune action |

- La prescription est conservée seulement pour les causes de **placement** :
  - créneaux insuffisants : le moteur compose sur le jour disponible le plus long ;
  - interférence gouvernée : c'est la génération rejetée sur le jour le mieux espacé qui est gardée.
- Les autres causes (refus du moteur, règle non gouvernée, douleur, sécurité, gouvernance) donnent BLOCKED. Rien n'est inventé.
- Pour une séance composée mais non placée, les raisons de composition du moteur et l'intention réellement utilisée sont persistées.
- Persistance (`zPersistedWeek`) : `record`, `demand` et `composedFor` (référence, jamais un placement).
- Programme : la demande porte `composedUnplaced: true`.

**Exécution manuelle** (« Faire maintenant ») :
- Elle utilise le même workout, le même runtime et `recordSessionExecution`.
- La prescription persistée n'est jamais recomposée.
- Le résultat porte la provenance `manual_from_unplaced`, et `date` est le jour RÉEL. Le statut et le placement de la demande sont inchangés (`UNPLACED → MANUALLY_COMPLETED` : `manual: true` dans la vue).
- La réalisation alimente :
  - l'historique ;
  - l'historique du moteur ;
  - les empreintes (sauf HYROX, comme avant) ;
  - `recentOf`, comme une séance « réalisée » ;
  - l'adhérence (`completedFromUnplaced`) ;
  - la rotation HYROX.
- La séance n'est jamais dérivée « manquée ». Une seconde soumission est refusée.

## 2. HYROX « Équilibré »

- **Profil** : `hyrox.focus: 'balanced' | 'specialized'`. Un profil antérieur (rôle seul) reste spécialisé ; il n'est jamais migré.
- **Programme** : plan à **rotation** `{ kind: 'balanced', goal }`, sans archétype. Le PROGRAMME assigne un rôle H2 par séance (surcharges par séance).
- **Politique gouvernée** :
  - `programme.rotation.candidates` : par sport et par objectif, archétype et stimulus ;
  - `programme.rotation.selection` : critères ordonnés (moins récemment réalisé, puis moins récemment assigné ; issues comptées comme réalisées gouvernées). En cas d'égalité, l'ordre de la liste départage ; chaque rôle est utilisé une fois avant toute reprise dans la même semaine.
- **TEST_ONLY** : `packages/programme/tests/rotation-governance.ts` (les cinq rôles H2, aucune préférence) ; en Beta 0, ces valeurs sont SIMULATION_ONLY.
- **Fail-closed** : en PRODUCTION, ou si la politique est absente, la rotation est indisponible (`ROTATION_UNAVAILABLE`). La demande reste alors sans archétype et devient non planifiée.
- **Frontière** : le Programme choisit le rôle, H2 compose la séance, M3 la place. Il n'existe aucun rôle `hybrid_race.h2.balanced`, et M3 ne change jamais un rôle.
- **UI** : « Équilibré » apparaît en tête des types de séance. Il est proposé par défaut pour « Préparer une course HYROX » tant qu'aucun type n'a été choisi.

## 3. Version

`BETA0_PLANNING_VERSION = 'beta0-m31'`. Une semaine non commencée est régénérée et expose ses séances composées mais non placées ; une semaine commencée est conservée.
